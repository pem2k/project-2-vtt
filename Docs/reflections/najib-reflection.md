# Project 2 reflection – Najib Hazel Mosquera
Building oPeN VTT with Parker taught me that AI coding tools are only as good as the context and the checks around them. Our shared AGENTS.md, the decision logs and the one branch per issue workflow gave every agent the same rules, so when I asked for a feature the result usually matched our conventions. When that context was missing, or when I let a bot resolve a merge conflict, things went wrong: Copilots automatic conflict resolution silently overwrote my GamePage changes in Sprint 1, and I had to repair them by hand.

Test driven development was the habit that paid off most. For every issue I committed a failing test first, then the code, then ran lint, format and the full test suite. That caught real breakage, like a maps test that failed when create_room changed, and it let me trust AI-generated code because the tests defined what "done" meant. I also learned to read AI output critically. During the CI work, Cursor reported failing checks, and I had to work out that they came from Windows line endings and a local .env file, not from the change itself.

Pair work was the hardest part. Twice I started work Parker had already done, the settings panel and the end to end tests, because I didn't ask first. Reviews also started late: in Sprint 1 we barely reviewed each others pull requests. In Sprint 2 we fixed that, and we each reviewed the others code on GitHub. Parker is awesome to work with. He has so much experience in building web apps, having him as a partner for the projects, it's a great help because of his background and knowledge creating apps. 

Our biggest mistake was reading the rubric late. Deployment, security scanning and documentation turned into a rush at the end. Next time I would compare our work against the requirements at sprint planning, deploy on day one, and post in Slack before touching shared work.
